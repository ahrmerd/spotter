## 1. What was built
- Settings tab: concurrent downloads (1–8), connections per file (1–16), speed limit, Wi-Fi only, resume on boot, default HLS quality (Best/1080/720/480/360), notifications, theme (system/light/dark), save folder, battery, view/export logs.
- All of those keys live in the existing Room `settings` KV table (`EngineSettings.toRows` / `fromRows`) and are applied through `DownloadManager.setSettings`, so they survive process death.
- Custom folder: `ACTION_OPEN_DOCUMENT_TREE`, persistable URI, `SafSink`. Empty URI keeps MediaStore `Download/Spotter`.
- Battery dialog once (`batteryPromptDone`); "Not now" and "Allow" both stop further prompts. Vendor note in the dialog and on the Settings row.
- `FreeSpace.check` before HTTP `setLength` and before HLS remux/copy. Error: `Not enough free space (need X, have Y)`.
- `EngineErrors.userMessage` maps connection, HTTP, space, HLS, SSL, DNS to short lines. Downloads row shows that, never a stack. Copy error uses `ErrorRedact`.
- `RotatingFileLog` under `filesDir/logs/` (256 KiB × 3), redacted on write. Settings can view and share via FileProvider.
- B7: `AdFrames.ignore(frameOrigin, pageUrl)`.
- Default HLS quality preselects the variant in the existing quality picker (`HlsDocument.Master.preferredIndex`).
- Notifications toggle skips the A2 waiting notification; the FGS progress notification stays (Android requires it while downloading).

## 4. Deviations from the plan (each with the reason)
- SAF was implemented instead of hiding it behind a flag. The write path already used a `ParcelFileDescriptor`; a tree URI is the same kind of sink.
- Max total connections is not a separate Settings row. Changing concurrent × per-file updates `maxTotalConnections` to their product (capped at 64).
- The FGS progress notification cannot be hidden while a download is running; the notifications switch covers the waiting/user channel.
