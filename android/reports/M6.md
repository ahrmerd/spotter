# M6 report (hardening and release readiness)

Branch `m6` (from `audit` after the M5 audit and its fixes). Work done by the auditor at the owner's request.

## What was done
- **R8 on for release** (`isMinifyEnabled`, `isShrinkResources`, default optimize rules). `app/proguard-rules.pro` is intentionally empty: library consumer rules plus the defaults were enough on every path tested; add a rule only together with the failure it fixes.
- **Signing without committing a key:** release config reads `android/keystore.properties` (git-ignored) or `SPOTTER_*` environment variables; with neither, the build writes an unsigned APK. `.gitignore` covers `*.jks`, `*.keystore`, `keystore.properties`. Instructions in `android/README.md`.
- **Lint clean** (`lintDebug`, `lintRelease`: no issues). Real fixes: `MediaExtractor.getSampleSize` is API 28 (minSdk 26), now guarded by `SDK_INT >= 28` (the buffer-grow path is the fallback on API 26 and 27); obsolete SDK checks removed; icon folder renamed `mipmap-anydpi`. Suppressed on purpose, with reasons in `app/build.gradle.kts`: `GradleDependency` (pinned versions), `OldTargetApi` (35 is the newest installed platform), `BatteryLife` (Play policy only; APK distribution).
- **Launcher icon:** adaptive and monochrome (themed) icon, indigo with a white download arrow in a ring.
- **Backups:** `dataExtractionRules` and `fullBackupContent` exclude everything, matching `allowBackup=false`.
- **README** with build, test, signing and a release checklist.

## Evidence (API 35 emulator unless stated)
- `./gradlew assembleRelease testDebugUnitTest`: BUILD SUCCESSFUL, **127 tests, 0 failures**; release APK 1.68 MB (the debug APK is about 17 MB). `apksigner verify`: signer `CN=Spotter Test` (a throwaway test key kept outside the repo).
- **Signed, minified release APK smoke test (HTTPS only, release blocks plain HTTP by design):**
  - launcher shows the new icon;
  - HTTPS file download (`Big_Buck_Bunny_360_10s_1MB.mp4`) completed;
  - HLS stream (Mux test stream, 64 segments) downloaded and remuxed with `MediaMuxer`: 36 MB MP4, ffprobe h264 512x288 + aac, 634.6 s, `ffmpeg -v error -f null` decode check prints nothing;
  - Settings opens; browser page `https://www.w3schools.com/html/html5_video.asp` shows "1 media" (the JS bridge survived R8);
  - process stayed alive throughout; no `ClassNotFound`/`NoSuchMethod` in logcat.
- Earlier (before the M5 merge) the same release path was checked with `-dontoptimize` to rule out R8 optimisation as the cause of one failed download; the failure turned out to be a transient 404 from the public test server, and a retry worked with full optimisation on.
