### A2 background resume
Decision: **pause and notify**. Items stay QUEUED. Android 15 will not start a `dataSync` FGS from a worker; we do not try a user-initiated data-transfer job in M2.
- `ResumeWorker` returns without calling `DownloadService.start` when nothing is QUEUED/RUNNING.
- `ResumeScheduler.enqueueNow` is ordinary WorkManager work (no expedited `dataSync` FGS).
- If `startForegroundService` throws `IllegalStateException`, a normal notification on channel `spotter_waiting` ("Downloads waiting / Tap to resume") opens `MainActivity`. No FGS.
- Successful FGS start cancels that notification.
- `onTimeout` still parks + schedules the worker; that path is still **NOT RUN** on a device.

## 1. What was built
- Room schema v2: `browser_tabs`, `bookmarks`, `history`, `sniffer_cache` + `MIGRATION_1_2`. Schema exported as `2.json`. Instrumented `Migration1to2Test` compiled, **NOT RUN**.
- Per-tab `WebView`: URL/search bar (DuckDuckGo), back/forward/refresh, desktop UA toggle, `CookieManager` (third-party accepted, flushed on pause), bookmarks and history.
- Popup blocker: `onCreateWindow` requires a user gesture; host blocklist in `shouldOverrideUrlLoading`; typed URL host is never blocked.
- Sniffer, three layers:
  1. `shouldInterceptRequest` observes only (always returns null), keeps Referer/Origin/Cookie/UA/Authorization, merges `CookieManager.getCookie`.
  2. Injected JS at page finish (`SpotterSniffer.media(url, kind)` — one validated method, http(s)/blob only).
  3. Probe: JS `UNKNOWN` http URLs get `RangeProbe` (HEAD/Range 0-0).
- Detected-media bottom sheet: newest first, play-event pinned, editable name from cleaned page title, Download. `blob:` and `PAGE_RESOLVER` do not enqueue.
- `DownloadListener` routes WebView downloads into `DownloadManager` with UA + cookies.
- Per-tab list in memory + Room `sniffer_cache`. First load after restore/process-death keeps the cache; later navigations clear it.
- Local pages in `android/tools/pages/` and Range media server `android/tools/media_server.py`, started by `android/tools/serve_m3.sh`.
- WebView hardening: `setAllowFileAccess(false)`, no file-URL access, geolocation denied, one JS bridge method.

## 4. Deviations from the plan (each with the reason)
- Search for non-URLs uses DuckDuckGo (`AddressBar.search`). The plan did not name an engine.
- HLS test page uses a tiny `hls-lite.js` that `fetch`es the master playlist and assigns a variant to `<video>`, not the full hls.js bundle (disk + no new dependency). The sniffer still sees the `.m3u8` request.

- Desktop UA is a Chrome-on-Windows string, not a setting.
