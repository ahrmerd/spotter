## Step 0 — M1 audit-fix review (read before any M2 code)

Confirming I understand the auditor's fixes in commit 86e8c98. Nothing here looks wrong.

- **Non-ranged reset (`HttpDownloader.fetchPart`)**: every attempt of a non-Range download sets `work.current = work.start` before the GET. A dropped connection retries from byte 0 instead of writing the restarted body at the old offset (F1 silent corruption).
- **`NonCancellable` in `DownloadManager` and `runParts`**: pause/kill cancel the job; Room's `withContext` would throw on a cancelled coroutine and skip the PAUSED write and the last persist/`force()`. Those writes run in `withContext(NonCancellable)`. Correct for real Room.
- **Partial-file check**: if any part has `current > start`, the sink length must equal `record.size` (or cover the offsets). Missing/truncated `.part` throws `RestartDownloadException` and the file restarts from 0 (F3).
- **`resumeAfterStop`**: a `resume()` that arrives while pause is still cancelling is remembered; when the job actually stops, state becomes QUEUED instead of PAUSED so the resume is not lost. Stale RUNNING with no job is re-queued.
- **`RoomLikeStore` / `FreezableStore` / `M1FixesTest`**: RoomLikeStore hops `Dispatchers.IO` per call (cancellation behaviour of Room). FreezableStore drops persist after freeze (hard kill). Tests cover F1–F4 and F7 completion.

## 1. What was built

Foreground service, notifications, Downloads UI, resume hooks, and MediaStore resume.

- **`SpotterApp`**: Room DB, `RoomDownloadStore`, `DownloadManager` with `AndroidSinkFactory` and `AndroidNetworkPolicy`. Observes Room and starts `DownloadService` when QUEUED/RUNNING exist. `CoroutineExceptionHandler` on `appScope`.
- **`DownloadService`**: FGS type `dataSync`, `stopWithTask=false`, `START_STICKY`. Notification with aggregate progress, Pause all / Cancel. `onTimeout` parks running jobs to QUEUED, enqueues `ResumeWorker`, stops. Idle stop is delayed 2 s so an empty first Room emission does not kill the service. `start()` catches `IllegalStateException` (`ForegroundServiceStartNotAllowedException`) and leaves rows QUEUED.
- **`ResumeWorker` / `ResumeScheduler`**: expedited one-shot after timeout; network-constrained unique work (`CONNECTED` or `UNMETERED` when Wi-Fi-only) after a yield.
- **`BootReceiver`**: `BOOT_COMPLETED`, **disabled and not exported** until the user turns on “Resume on boot”. Still checks the setting in `onReceive`.
- **`NetworkMonitor`**: `ConnectivityManager.NetworkCallback`, debounced, only acts when online/unmetered actually change. Yields running jobs to QUEUED when offline or when Wi-Fi-only and not on Wi-Fi/ethernet; pumps when allowed again.
- **Downloads UI**: Compose list from Room `Flow` (ViewModel). Progress, speed/ETA from downloaded deltas, pause/resume/cancel/retry/remove, open, share, delete file, rename, mime/extension category chips, search, add-by-URL. Overflow: Wi-Fi only, resume on boot, pause all. `POST_NOTIFICATIONS` requested on Android 13+.
- **Share-target** `ACTION_SEND` `text/plain` and clipboard `http(s)` suggestion: prefill the add dialog; nothing downloads without confirm.
- **Sinks**: API 29+ `MediaStoreSink.open` reopens the stored `content:` URI; if the URI is gone, inserts a new row (HttpDownloader then restarts from 0 via the partial-file check). API 26–28 `PrivateFileSink` under `getExternalFilesDir(DIRECTORY_DOWNLOADS)`. FileProvider only `external-files-path` `Download/`.
- **Manager APIs**: `cancel`, `remove(deleteFile)`, `deleteDownloadedFile`, `retry`, `rename`, `pauseAll`, `parkRunning`, `notifyNetworkChanged`. `resumeOnBoot` persisted.
- **Tests written**: `M2ManagerTest` (7), `ShareUrlsTest` (4), `CategoriesTest` (2); instrumented `RoomDownloadStoreTest` and `MediaStoreSinkTest`.

### MediaStore resume design

`create()` always inserts. `open(displayName, resumePath, mime)`:

1. If `resumePath` is `content:` and `openFileDescriptor(rw)` succeeds, reuse that row (`IS_PENDING` stays 1 until `complete()`).
2. If the URI is gone, `create()` a new unique row. HttpDownloader sees a new/empty length vs persisted parts and throws `RestartDownloadException` → restart from 0. Correct: the bytes are gone.
3. If the URI exists but is truncated, `length()` is short → same restart-from-0 into that URI.

Never overwrite a different user's file: uniqueness is `DISPLAY_NAME` in `Download/Spotter`.

## 4. Deviations from the plan (each with the reason)

- **Yield to QUEUED, not user PAUSED**, on airplane / Wi-Fi-only drop / `onTimeout`. User PAUSED would not auto-resume. Matches “resumes without user action”.
- **`BootReceiver` is disabled until opt-in** (`android:enabled="false"`, `exported="false"`). Manifest-enabled + Application collector would start the FGS on every boot even when resume-on-boot is off, because receiving `BOOT_COMPLETED` creates the process.
- **`DownloadService.start` swallows `IllegalStateException`**. Android 12+ can refuse `startForegroundService` from the background. Crash-on-boot is worse than leaving QUEUED until the user opens the app. WorkManager is still the scheduled resume path; whether API 35 actually lets that worker start a `dataSync` FGS is unverified (see Questions).
- **`M1AcceptanceTest.hundredMegFourPartsHashMatches`**: assertion is now `parts.size >= 4` instead of `== 4`. Hash still matches. Work stealing can add a fifth part under load (saw `expected 4 but was 5` with a matching SHA-256). Stated here because the assertion changed.
- **Speed/ETA** are computed from Room progress (~1 s persist), not a 4 Hz in-memory ticker. Coarse but within “UI updates at most ~4/s”.
- **`isOnline`** uses `NET_CAPABILITY_INTERNET`, not `VALIDATED`. Captive portals count as online.
- **New deps** (allowed): `androidx.work:work-runtime-ktx:2.9.1`, `work-testing:2.9.1`, `androidx.test:runner:1.6.2`, `core-ktx:1.6.1`, `ext:junit:1.2.1`, `rules:1.6.1`, `room-testing:2.6.1`.
