## 1. What was built

Engine core for plain HTTP files under `dev.ahmed.spotter.engine`, JVM-testable, no UI wiring.

- **Probe** (`engine/net/RangeProbe.kt`): `Range: bytes=0-0` → size, range support, filename (`Content-Disposition`, URL, MIME), `ETag`, `Last-Modified`.
- **HttpDownloader**: default 4 parts (1–16), positioned writes into a pre-allocated `.part` file, work stealing (upper half of the slowest remaining part, min split 1 MiB), resume from persisted part offsets, `If-Range` / ETag / Last-Modified validation (restart if changed), exponential backoff (1s…30s, 8 attempts, reset on progress). 403/404/410 → `NEEDS_REFRESH` with no retry loop.
- **DownloadManager**: `QUEUED → RUNNING → (PAUSED | DONE | ERROR | NEEDS_REFRESH)`, max concurrent downloads (default 3), total connection cap (default 16), optional token-bucket speed limit, Wi-Fi-only behind `NetworkPolicy`.
- **Room schema** v1: `downloads`, `parts`, `settings` (KSP, exported to `app/schemas/.../1.json`). `RoomDownloadStore` maps to domain records. JVM tests use `InMemoryDownloadStore`.
- **FileSink**: positioned `FileChannel` writes. `PrivateFileSink` (used by tests). `MediaStoreSink` for `Downloads/Spotter` on API 29+.
- **Filename**: no `/` or NUL, no leading dots, 200-char cap, add extension from MIME/URL, never overwrite (`name (1).ext`).
- **Test server**: `app/src/test/.../RangeTestServer.kt` — Range/206/Content-Range, ETag, If-Range, throttle, mid-stream disconnect, no-Range mode, 403 after N requests, byte and request counters.

Production UI is unchanged (`Downloads (todo)` / `Browser (todo)`). Service/notifications are M2.

## 4. Deviations from the plan (each with the reason)

1. **Test server is `java.net.ServerSocket`, not `com.sun.net.httpserver`.** Android unit tests compile against `android.jar`, which does not include `jdk.httpserver`. Behaviour required by the testing guide is implemented (Range/206, If-Range, ETag, throttle, disconnect, no-Range, 403-after-N, counters).
2. **Process kill is simulated on the JVM** (cancel jobs, keep the store, construct a new `DownloadManager` which recovers `RUNNING` → `QUEUED` and resumes). Not an Android process kill. That belongs with the M2 service.
3. **Room is compiled and schema-exported; JVM tests use `InMemoryDownloadStore`.** Room needs an Android runtime. No Robolectric was added.
4. **Test-only libraries:** `junit:4.13.2`, `kotlinx-coroutines-test:1.9.0`, `okhttp3:mockwebserver:4.12.0`, `okhttp3:okhttp-tls:4.12.0`. The last two are for the HTTPS HTTP/2 negotiation test (lesson 8.1 / testing guide).
5. **Debug network security config** allowing cleartext to `10.0.2.2` / `localhost` / `127.0.0.1`, and `android:usesCleartextTraffic="false"` on the application. This is a non-negotiable from section 4; slightly early vs M2.
6. **Total connection cap default is 16** (plan did not name a number). Connections per file stay 1–16, default 4. Concurrent downloads default 3.
7. **Work-steal minimum remainder is 1 MiB**, same as the desktop engine.
8. **403 fixture** fails after N *requests* (probe + some parts), not mid-body of one socket. Still “mid-download” (file incomplete, later requests 403).
9. **Disconnect fixture** drops every 2nd request after 32 KiB so the retry path is guaranteed. A pure random coin-flip run completed in 2 requests and would not have asserted retries.

KSP plugin `2.0.21-1.0.28` and Room `2.6.1` were added as the plan allows.
